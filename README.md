# ETL статистики грейдера на Python

Итоговый проект курса Python (НИЯУ МИФИ, магистратура, 2026).

Скрипт забирает у API попытки студентов в редакторе кода, приводит их к
плоскому виду, проверяет, загружает в локальную PostgreSQL, пишет подробный лог,
а в конце выгружает дневную статистику в Google Sheets и присылает письмо.

## Что делает

1. **Скачивание.** `requests.get` к API статистики учебной платформы (адрес в `API_URL`) с параметрами
   `client`, `client_key`, `start`, `end` (время на сервере в UTC). Интервал режется на сутки.
   Сетевые ошибки и ответы 5xx/429 повторяются до 3 раз, остальные статусы сразу
   пишутся в лог как `ERROR` со `status_code`. Ключ клиента в лог не попадает.
2. **Обработка.** `passback_params` приходит строкой с repr словаря Python, поэтому
   разбирается `ast.literal_eval` (JSON как запасной вариант). Из него достаются
   `oauth_consumer_key`, `lis_result_sourcedid`, `lis_outcome_service_url`.
3. **Валидация.** Проверяются типы и допустимые значения, записи с ошибками
   пропускаются и попадают в лог с номером и причиной (см. правила ниже).
4. **Загрузка в PostgreSQL.** Таблица `grader_attempts`, пакетная вставка
   `execute_values`. Загрузка идемпотентна: повторный запуск за те же сутки
   не создает дубликатов.
5. **Лог.** Файл `logs/ГГГГ-ММ-ДД.log` по текущей дате, в консоль то же самое.
   Старые логи удаляются, остаются файлы за сегодня и два предыдущих дня.
   Пишутся этапы (скачивание началось/завершилось, заполнение базы
   началось/завершилось), время работы и все ошибки.
6. **Звездочка 1.** Дневные агрегаты из базы (попытки, run/submit, успешные сабмиты,
   доля успешных, уникальные студенты и задачи) в лист `daily_stats` Google Sheets.
   Строка за уже выгруженный день обновляется, новая добавляется. Задача определяется
   как пара «курс + блок» из `lis_result_sourcedid` (формат `курс:версия:блок:студент`):
   значение целиком уникально для каждой пары студент-задача, поэтому по нему задачи не считаем.
7. **Звездочка 2.** Письмо через `smtplib` + `ssl` (Gmail) с итогами запуска или
   с текстом ошибки.

## Структура

```

grader_etl/

    config.py            настройки из .env
```

## Структура таблицы

| Поле | Тип | Комментарий |
| --- | --- | --- |
| `user_id` | TEXT NOT NULL | `lti_user_id` из ответа |
| `oauth_consumer_key` | TEXT | в данных за 31.05.2026 пустой у всех записей, пустое значение превращается в NULL |
| `lis_result_sourcedid` | TEXT NOT NULL | блок с задачей в ЛМС |
| `lis_outcome_service_url` | TEXT | адрес в ЛМС для оценки, бывает NULL |
| `is_correct` | BOOLEAN | `1`/`0` из API превращаются в true/false, у `run` NULL |
| `attempt_type` | TEXT NOT NULL | `run` или `submit` |
| `created_at` | TIMESTAMP NOT NULL | время в UTC; значения со смещением пересчитываются в UTC |
| `id`, `loaded_at` | служебные | суррогатный ключ и время загрузки |

Уникальность: `(user_id, lis_result_sourcedid, attempt_type, created_at)`.

## Правила валидации

Запись **пропускается** (и пишется в лог), если:
- `passback_params` пустой, не разбирается или не является словарем;
- нет или не строка `lti_user_id` или `lis_result_sourcedid`;
- `attempt_type` не `run`/`submit`;
- `is_correct` не `null`, не `0`/`1` и не булево;
- `attempt_type='run'`, а `is_correct` не `null` (у `run` результата проверки нет, у `submit` значение может быть true, false или NULL);
- `created_at` отсутствует или не является датой-временем (дата со смещением часового пояса не отвергается, а пересчитывается в UTC; без смещения считается уже UTC);
- `oauth_consumer_key` или `lis_outcome_service_url` есть, но не строка.

Запись **сохраняется** с NULL, если `oauth_consumer_key` или `lis_outcome_service_url`
отсутствуют. Решение принято по данным: за 31.05.2026 из 500 записей у 148
(в основном `run`) нет `lis_outcome_service_url`. Если их выбросить, потеряется
около 30% попыток и исказятся метрики активности. Число таких записей пишется в лог.

## Ключевые решения

- **Не терять данные.** За 31.05.2026 у 148 из 500 записей нет `lis_outcome_service_url`; они сохраняются с NULL, иначе потеряется около 30% попыток.
- **Что считать задачей.** Пара «курс + блок» из `lis_result_sourcedid`: значение целиком уникально для каждой пары студент-задача.
- **Идемпотентность.** Уникальный ключ в базе: повторный запуск за те же сутки не создает дубликатов.
- **Проверка результата.** Загруженные строки сверены с ответом API, агрегаты за сутки совпали с прямым SQL и с листом Google Sheets.

## Правки по результатам ревью (31.10.2026)

1. **`attempt_type` и `is_correct`.** README требовал NULL у `run`, но код проверял поля независимо, и `run` с `is_correct=true` попадал в базу. Теперь такая запись пропускается и попадает в лог; добавлены тесты.
2. **Часовые пояса.** Время со смещением больше не теряет смещение молча: `grader_etl/timeutil.py` пересчитывает его в UTC (разбор в `transform.py` и `api_client.py`), поэтому интервал со смещением не ломает `split_into_days`. Добавлены тесты, в том числе на смену суток.

## Запуск

Нужны Python 3.11+ и запущенный PostgreSQL с созданной базой.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # заполнить значения
.venv/bin/python main.py --date 2026-05-31
```

Параметры:

| Параметр | Что делает |
| --- | --- |
| `--date ГГГГ-ММ-ДД` | сутки для загрузки, по умолчанию вчера |
| `--start`, `--end` | интервал `ГГГГ-ММ-ДД ЧЧ:ММ:СС` (указывать вместе) |
| `--no-sheets` | не выгружать в Google Sheets |
| `--no-email` | не отправлять письмо |

Актуальные данные в API есть только до 2026-06-01, поэтому запуск без `--date`
вернет пустой день.

Ключи Google Sheets (JSON сервисного аккаунта) и пароль приложения Gmail хранятся в
`service_account.json` и `.env`, оба файла в `.gitignore`.

## Тесты

```bash
.venv/bin/python -m pytest -q
```

Тесты базы работают в отдельной временной схеме и не трогают рабочую таблицу.
Если PostgreSQL недоступен, они пропускаются.

## Наблюдения по данным (31.05.2026)

- Ответ API за сутки пришел за 30-35 секунд, 500 записей.
- Две половины суток вместе дают столько же записей, что и сутки целиком, значит
  ограничения на размер ответа нет.
- Загружено 500 попыток, из них 276 `submit`, 134 успешных (48,55%), 35 студентов,
  130 задач (курс + блок). Загруженные строки сверены с ответом API за окно 10:00-10:59
  (20 записей, совпадение полное), агрегаты за сутки совпали с прямым SQL и с листом Sheets.
